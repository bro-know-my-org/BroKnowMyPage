# 从订阅 ChatGPT 到部署自己的 API 入口

打算水一篇怎么部署订阅的文章。整件事大概就是：先把账号订阅搞定，再找台服务器，装个 CPA 或 sub2api，把账号接进去，最后在自己的客户端里用。

## 先把 ChatGPT 订阅搞定

常见路子大致分四种：

1. 官网直充。
2. Google Play 或 Apple App Store 内订阅。
3. 「我有一个朋友」。
4. 买成品号或者找人代充。

### 官网直充

这条路最直接：准备好银行卡，在 ChatGPT 官网登录自己的账号，选订阅、付款，结束。

选卡的话，优先找一张非大陆发的 Visa 或 Mastercard。但能不能扣上款，还得看发卡地区，OAI支持的地区还是有些不一样的。

### Google Play / Apple App Store

另一条路是在官方 ChatGPT 手机 App 里订阅，付款交给 Google Play 或 App Store 处理。

这时可以尝试用大陆发的 Visa、Mastercard，具体看商店地区和卡的支持情况。

苹果还有礼品卡这条路：买对应商店地区的礼品卡，充进 Apple 账户余额，再拿余额付订阅。注意礼品卡地区得和账户对上，先确认能用再买。

付款条件可以对照 [Apple 各地区支持的付款方式](https://support.apple.com/zh-cn/111741)、[Apple 充值卡兑换说明](https://support.apple.com/zh-cn/118242)和 [Google Play 国家／地区说明](https://support.google.com/googleplay/answer/7431675?hl=zh-Hans)。

### 「我有一个朋友」

如果你有一个肉身在海外、又愿意帮忙的朋友，那很多事情就简单了。卡、当地付款方式、充值操作，找朋友商量着来就行。

这招甚至可以延伸到 Claude Code：如果朋友那边有账号和能跑的环境，也愿意让你用，直接 SSH 到他家里那台电脑上，在远端跑 Claude Code 就行。

当然，Claude 那边的订阅和权限要另外准备。这里的核心技术是：我有一个朋友。

### 成品号 / 代充

成品号不推荐。账号怎么来的、出了问题找谁，都说不好。

代充我没试过，不做评价。

## 中途可能跳出来的验证

除了付钱，有时还会碰到验证。不一定每个人都有，也不一定在订阅的哪一步冒出来。

### 大家常说的 KYC / 身份或年龄验证

可能会碰到跳转到 Persona 的验证页面。

我自己没触发过，所以这里没有亲测的过审教程。

🐟 上能看到一些代办（不推荐 整封号了就好玩了），也可以再次启动「我有一个（外国）朋友」。

### 手机号验证

也可能跳手机号验证，我也没遇到过。

先看页面接受哪些号码、有什么要求。有自己能长期控制的号码就优先用自己的；朋友可以帮你了解当地怎么办号。别只想着这次验证码收到就行，后面如果还要验证，号码得找得回来。

折腾到这里，账号的订阅状态确认生效了，就可以往下走了。

## 再找一台放服务的服务器

接下来要放的是转发和管理服务。模型在上游跑，你的服务器主要处理请求、授权和日志，个人低并发用不着一上来就买很大的机器。

只跑轻量转发的话，**1 核 CPU、1 GB 内存够起步了**。如果选 sub2api，还要把 PostgreSQL、Redis 的占用算进去；后面再加 New API、攒日志或者多人并发，就按实际吃的内存和负载加配置，反正我1c1g够了。

服务商自己挑，来路不明的野鸡商家别碰。重点看线路、稳定性、售后，以及服务器出口能不能正常访问你要用的服务。家宽出口的方案也行，但「家宽」两个字不保证账号就一定没问题。

用朋友家里的电脑跑的话，也要想好断电、断网和重启之后怎么办。

### 哦对，还有域名和 HTTPS

准备一个域名，解析到服务器，再用 Caddy、Nginx 之类的反代配好 HTTPS 和证书。加密连接靠 HTTPS/TLS，域名买完这一步也得跟上。

如果已经通过 VPN、SSH 隧道之类的方式加密访问了，域名要不要另配可以看你自己的网络方案。直接在公网用明文 HTTP 传密钥、授权信息和聊天内容就算了。

## CPA / sub2api，选一个装

这里的 CPA 指 **CLIProxyAPI**。它和 sub2api 都能接入项目支持的账号授权，给客户端提供可调用的接口。

| 项目 | 部署文档 |
| --- | --- |
| [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) | [官方中文手册](https://help.router-for.me/cn/) |
| [sub2api](https://github.com/Wei-Shaw/sub2api) | [README 中的部署方式](https://github.com/Wei-Shaw/sub2api/blob/main/README_CN.md#部署方式) |

挑一个顺手的，跟着文档装就行。sub2api 的 Docker Compose 部署包含数据库和 Redis，记得一起配置和持久化。

服务起来以后，按项目支持的方式把自己的账号加进去。以 ChatGPT 账号为例，具体接入走 Codex 等授权流程。

然后给客户端创建调用密钥，填上你的接口地址。自己用的话，链路到这里就够了：

```text
自己的客户端 → HTTPS 入口 → CPA 或 sub2api → 上游账号服务
```

管理密码、客户端调用密钥、上游账号授权各自保管好。给客户端用的是调用密钥，账号授权文件留在服务端。

## 想分人记录用量，再加 New API

如果想给几个人分别发密钥、记录谁用了多少、设置各自额度，可以再部署一个 [New API](https://github.com/QuantumNous/new-api)。安装方式看它的[官方部署文档](https://docs.newapi.ai/zh/docs/installation)。多人用之前，也要确认你的订阅允许这么共享。

把前面 CPA 或 sub2api 的兼容接口配成 New API 的上游渠道，再给不同的人建用户或发密钥。客户端统一连 New API：

```text
各自的客户端 → HTTPS 入口 → New API → CPA 或 sub2api → 上游账号服务
```

同机部署的话，让两层服务走本机或容器内网通信就行。注意客户端用的是 New API 发的密钥，上游渠道那边填转发服务的地址和密钥。

这一步按需加。如果你选的面板本身就能分用户、统计用量，直接用它的功能就行，也省得多维护一层。

## 最后跑一次确认

打开客户端发一条简单请求，确认能正常回；平时要用流式输出的话，也实际试一下。

再去后台看看账号是不是正常的、请求有没有记下来。加了 New API 的话，顺便确认这次请求记在了对应的用户或密钥下面。

把服务的开机自启、账号授权和数据库备份安排好，就大功告成了。
